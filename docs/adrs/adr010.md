# Docker packages the CLI worker

## Status

Accepted

## Context

The intake worker is a one-shot CLI (`python -m src.pipeline`), not an HTTP server. LiteLLM already reads provider keys from the environment. Graders and local demos need a repeatable container without standing up Postgres, Redis, Azure, or a mock model.

## Decision

- Ship a **Dockerfile** whose entrypoint is the same CLI. The container **exits when the command finishes**.
- Inject secrets with **`env_file: .env`** / `docker run --env-file`. Never copy `.env` into the image.
- Bind-mount `inbox/`, `bus/`, and `checkpoints/` so HITL artifacts stay on the host (same object-store contract as adr002).
- Do not add sidecar services in Compose. The LLM provider is reached over the network using keys already in `.env`.

## Consequences

Local venv and Docker run the same code path. Compose is a convenience wrapper, not a second orchestrator. Step types do not change.
