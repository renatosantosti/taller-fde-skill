# Bus port with a file bus; Azure Service Bus on the map only

## Status

Accepted

## Context

HITL must travel on a barramento so production can use Azure Service Bus. Shipping the Service Bus SDK in this repo would require a namespace and hide the contract behind cloud setup.

## Decision

Define a `Bus` port (`publish` / `get`) with `IntakeNeedsReview` and `IntakeDecision`. Implement **FileBus** (JSON under `bus/`). Name Azure Service Bus on the deployment map only. No Service Bus SDK in this delivery.

## Consequences

`resume` writes a decision to the file bus and continues the checkpoint — the same path a Service Bus subscription would call. Reviewers still get a human-readable packet in `inbox/needs_human/`.
